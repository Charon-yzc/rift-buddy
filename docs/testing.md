# 玩家行为测试

测试以玩家能完成操作、窗口之间状态一致、没有越权写入为准。测试数量、指定英雄上榜、旧攻略文字和固定资料条数都不是验收目标。当前流程与历史兼容必须分开，不能把旧资料改个版本号当作当前数据。

## 从玩家操作验收细节

用当前安装候选进一次匹配、排位和海克斯的隔离流程。每次从实际入口开始，记录玩家点了什么、看到什么、要等多久。网络回包放慢或颠倒一次，再把同样的操作做一遍。窗口按默认大小、窄侧栏、125% 文字和小工作区试用。

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 开软件准备开局 | 分别先开助手和先开客户端，从大厅走到选人 | 需要权限时只在合适时机提示一次。连接后进房、侧栏出现都无需重复点击。关闭相关开关后照选择执行 |
| 大厅预选进入本局 | 在大厅点头像，模拟首轮可选范围缺失、实际分路变化，再模拟玩家已经在客户端换了英雄 | 资料齐全后按本局分路配置。玩家已在客户端选别的英雄时保留该选择 |
| 按住头像遇到刷新 | 鼠标按下头像，插入客户端同步或资料刷新，再松开。上一套配置慢时再点另一个头像 | 第一次松手即发出原头像预选。界面先确认选人，配置继续在后台处理。最后一次有效选择决定当前英雄和配置。被队友抢选时说明原因，保留已成功的选择 |
| 提议带旧配置 | 在队友提议中点击可选头像，再从提议详情打开发送方配置 | 即使发送方配置已过期，也先预选英雄，再按当前英雄与分路加载常用配置。查看旧方案时保留版本提示，且没有额外的预选或写入 |
| 看自己的配置 | 在组合候选里点头像，进「我的配置」，再手选社区方案。切英雄、分路及游戏模式各一次 | 默认跟当前英雄、分路和 OP.GG 常用配置。社区方案可明确选，切换时来源、符文、装备、D/F 和加点都对应当前方案。别人的方案预览保持只读 |
| 商店装备集 | 预置自建、第三方、其他英雄和其他模式的旧开黑搭子装备集，应用本局方案后再换英雄 | 新开黑搭子方案写入并回读后，清理其他已确认的开黑搭子装备集。自建、第三方文件逐字节保留。另在真实商店观察首次打开的标签与下拉顺序 |
| 看推荐和换一批 | 在有常用统计、无统计、统计分批到达时各跑一次。滚到中间，触发后台更新，再点换一批 | 可用候选连续可看。后台统计不让列表跳动，明确换批可采用新数据。冷启动、热换批、选人变化分别记点击到新候选稳定的时间，目标是正常场景亚秒；配置同步单独计时 |
| 提议后继续选人 | 按住投票按钮时插入同步，松手后再换批，最后模拟队友选走冲突英雄 | 一次点击只给原提议改一票。有效提议、投票和阅读位置保留。确认冲突时失效的提议退出 |
| 自动与手动「我们」 | 模拟开黑成员和普通队友各占一路，再拖动五路中的英雄。手动改范围并进入下一局 | 自动避开普通队友占用的位置，保留开黑成员。拖动时玩家归属、分路、参考范围一起变。手动范围本局有效，下一局回到自动 |
| 排位、匹配和曲线 | 从排位切到匹配，观察本人锁定、己方全部锁定、敌方公开选人三个时点 | 排位参考全队，匹配回到「我们」。个人曲线直接出现在「我的配置」，己方完整后阵容页直接展示曲线。若显示双方胜率，同一时点互补，悬停能读时间和值。隐藏英雄保持未知 |
| 海克斯备选和配置 | 分别打开无选人状态、实际备选池和已选英雄配置。点可换头像与队友头像，试总池及四轮标签 | 有真实池时同一组头像带胜率和「我／我们／队友」标记。可换头像执行切换，队友头像只打开参考。总池和轮次按可验证资料显示。配置首屏可快速对照强化、装备和加点，图标悬停能读详细文本 |
| 局内小窗 | 进入模拟对局，分别试默认位置、收起、展开、滚轮、置顶、贴边和恢复。另在真实游戏中只观察前台焦点和默认位置 | 经济窗一眼能读双方装备价值，右侧配置先强化后装备。收起仍看得到首套完整配置，展开用滚轮浏览。悬停避开鼠标和边缘，拉手够得着。开局、拖动窗口及焦点恢复不打断游戏 |
| 鼠标和键盘 | 在图鉴滚到中间悬停一件装备并插入无关刷新。在房间或搜索框用中文输入法输入，再试 Esc 和 Tab | 提示和滚动位置保留。换装备模式或更新该装备资料后显示当前内容。输入法候选和光标位置不丢。关闭弹窗后焦点回到仍有效的原入口 |
| 短断线和赛后 | 选人时令客户端状态请求短断，再返回同一局。另一轮主动离房，结算后关闭评分再重连 | 原组队身份恢复后继续留房，换局或换号需重新确认。海克斯备选池短断时仍可查看，恢复后才能换人。主动离房不被旧回包覆盖。关闭本局评分后不会反复弹出，复盘仍打开对应对局 |
| 侧栏锁定、重连和排行 | 锁定后打开房间，断线重连。到排行选中搜索词中间几字，模拟选人更新；滚动后切分路 | 首次锁定在阵容页自动打开本人配置。房间和排行留在原页，搜索框保留焦点和选区，换分路回到新榜单顶部 |
| 安装、更新和资料 | 从实际旧版通过更新页升级，检查下载位置、暂停、继续、取消。再测完整包修复与离线启动 | 有兼容补丁就用增量。失败说清原因，下载位置可打开。设置、收藏和其他应用的快捷方式保留。版本改动页默认显示当版，资料缺失明确标示 |
| 主界面一眼能懂 | 从主窗口依次进历史战绩、实时对局、收藏、图鉴、各路排行、版本改动、海克斯手册、反馈和设置 | 导航与页面内容不重复占空间，来源和样本只出现一次。空状态能看出下一步，失败可恢复。反馈明确显示发送成功或失败，截图和文字可先检查 |

自动化负责复现时序、记录数值和检查可访问的入口。真实游戏复查只观察可读性、焦点、窗口位置及响应感，使用测试账号或训练环境，由玩家手动操作。报告分别注明已通过的隔离场景、已现场核对的场景和仍缺证据的场景。现场记录包含软件和游戏版本、窗口尺寸、系统缩放、操作步骤及出现问题时的画面。响应慢时分别记录首屏、换批、点击确认和后续配置完成的时间。

## 历史资料怎样测

`tests/fixtures/snapshot-16.20`、`snapshot-16.21` 保留原版本和来源。它们用于旧保存身份、解析、签名、撤回、完整配置及迁移回归，不证明当前版本的攻略可执行。当前包验收从实际 `data/` 构建，不把旧统计或旧攻略重新标记为当前。

删除重复的旧英雄攻略复演时，先把独有的保护迁移到通用用例：来源撤回、成员绑定、装备模式、技能合法性、收藏身份和队友只读仍必须覆盖。特殊英雄真实的技能规则不是过时文本快照，不能一并删除。

本轮移除的旧 cookbook 套件包括 `trio-dedicated-loadouts`、`next-skill-scopes`、`trio-mechanics-1620`、`loadout-review`、`community-maintenance`、`duo-plays`、`party-trio-expansion`，以及 11 个重复的 Hex 英雄/旧机制套件。相关通用保护迁入上表的配置、技能、Hex 玩家契约和原始解析测试。未再被调用的 `smoke-draft` 固定旧界面数量脚本也移除；换位、取消过期计算和刷新分别由当前双窗验收及 continuity 用例负责。

## 执行与判定

```powershell
pnpm test
pnpm check
pnpm catalog:validate
pnpm package
node scripts/inspect-package.mjs --verify-current
```

随后按 `.github/workflows/ci.yml` 执行打包验收。优先运行当前包的点击、双窗、当前资料、海克斯、局内小窗、统计和增量升级；历史包单独标记。所有客户端、聊天、符文、回放和房间流量使用隔离模拟，测试不得操作正在进行的真实游戏。

性能测试要记录测量对象、运行环境、模拟网络延迟及冷/热状态。不得用本机某一次很短的运行时间宣称所有玩家都能亚秒响应；确定性的优先级、缓存失效和旧结果取消仍须断言。

失败必须定位为产品缺陷、测试缺陷或环境失败，并保存证据。已有失败仍是失败，不能以“没有新增失败”代替通过；不能删除失败断言或加入条件跳过让结果变绿。平台专属跳过需报告具体原因，不能当成已验收。
