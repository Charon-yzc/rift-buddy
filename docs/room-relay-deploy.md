**桌面提供局域网与中继两个自愿开启的通道。0.39.0 中继输入预填用户提供的 `wss://room.riftbuddy.dpdns.org`，保留已保存的自定义地址，也可自行提供可信的 `wss://` 服务。预填地址本身不是生产部署与双机连通验收证据。** 2026-10-12 使用独立原生 WebSocket 重新连接该公网地址：双向 2／3／4／5 人方案的模式、装备、完整符文、加点、召唤师技能与组合职责均逐项一致，最大五人快照约 39 KB；新加入的第三个测试客户端也收到完整三人快照。此前 2026-10-11 的仅阵容／4009 限制在本次样本中没有再出现。0.44.0 桌面端移除默认地址的仅阵容发送限制，统一发送经白名单清洗的完整方案；旧版助手需要升级才能完整发送。仓库 Worker 已在 Wrangler 4.149.0 本地真实 workerd/Miniflare 验证三人配置、方案晚加入重发与海克斯属性方案。公网本次使用合成公开英雄数据、同一台机器的独立连接；两台 Windows、不同运营商、Workers 休眠与慢接收端、真实国服连续对局仍待验证。

## 完整准备文件

0.40.0 开发版在“开黑房间”提供“导出当前准备”和“打开队友准备”。无需建房即可导出当前所选成员的装备计划、符文、召唤师技能、加点、来源和已采用组合职责，自行通过私聊发送 JSON 文件。接收方先查看成员配置与资料版本，再主动采用符文／加点／召唤师技能；装备单独参考，写符文仍需本人核对英雄并点击替换。文件内容不会自动更新或替换阵容，不包含收藏备份、房间口令或客户端账号。默认公网中继的能力保持上述实际验证范围。

## 已有协议

- 每个六位房间号一个 Durable Object；WebSocket 握手后仅转发经白名单重建的昵称、公开阵容、模式、所选配置快照、组合职责和加入／离开通知。配置含装备编号、完整符文、召唤师技能、加点及来源说明，不包含 LCU 凭据、riotId、战绩、隐藏敌人或任意个人设置。
- 加入时发送六位口令的 SHA-256，服务不接收明文口令。空间很小，哈希可以被枚举，不能当作强身份认证。最后一位已加入成员离开后清除口令哈希。
- 不保存共享状态；客户端在 welcome / join 后重新发送当前阵容、模式、完整配置和组合职责。重连期间保留最新本机分享，重新握手后重发；断线时清除过期队友表。首次传输失败最多尝试三次；连接后连续八次失败停止重连，界面提示离开后重新加入，明确拒绝不会反复重试。
- 不主动写请求日志；Cloudflare 平台可观察请求与连接元数据。口令哈希存于 Durable Object storage，昵称等连接附件由平台托管，不能承诺平台完全不保留数据。
- 文本帧按 UTF-8 字节限制为 64 KiB；白名单和字段长度另受限制。房间最多 12 位成员，尚未握手的连接不接收成员消息。
- 每个房间最多接收 20 个连接（含未握手和正在关闭的连接）；清理未握手连接时，须等平台实际释放容量。容量未释放时返回 503，稍后重新尝试；关闭中的连接不能继续完成握手或发布。
- 每条连接的消息与 UTF-8 字节采用令牌预算：允许突发 16 帧／1 MiB，之后每秒补充 4 帧／128 KiB；超过预算只关闭该连接。预算放入连接附件以跨休眠保留；发送失败只关闭对应接收者。此代码限制不保证运营商连通、平台费用上限或慢接收端实际队列行为，仍需真实 Workers 验证。
- 桌面接收端另限制房间消息突发为 600 帧、每秒补充 60 帧，心跳不计入；允许十二人房间持续正常分享，不把会话累计消息数当作刷屏。此处也是代码限制，尚无真实长时间跨网验证。

## 组队房间自动连接（0.50.0，未做双机实测）

用户明确勾选“自动连接组队房间”后，助手在英雄联盟预组队大厅（非自定义、至少 2 名开黑成员）里用 `/lol-lobby/v2/lobby` 的 `partyId` 派生房间码与口令：`SHA-256("rift-buddy/auto-room-code/v1:" + partyId)` 与 `SHA-256("rift-buddy/auto-room-pin/v1:" + partyId)` 各取前四字节按大端无符号整数对 1,000,000 取模，再左侧补零到 6 位，正好沿用现有协议，服务端与 Worker 无需改动。`partyId` 是服务端生成的组队标识；社区抓包里它与 `chatRoomId`、`chatRoomKey` 是同一个字符串，助手只读 `partyId` 字段，从不读取 `chatRoomId`、`chatRoomKey`、`mucJwtDto` 等聊天凭据。标识只在主进程与授权助手进程之间传递，发往沙箱渲染层前会被剥除，不落盘、不上传。房间昵称使用本机公开游戏 ID（`gameName#tagLine`），会随分享内容经中继转给房间成员，运营者可见；接口没有提供公开游戏 ID 时回落到“我的昵称”，两名队友使用同一昵称时中继会拒绝其中一人（昵称重复），需各自设置不同的“我的昵称”或手动加入。本机身份隐藏时既没有组队标识也没有公开 ID，不会自动连接，可继续手动加入。

知道 `partyId` 的人可以算出房间码与口令，6 位口令本来就是弱限制：自动房间的信任边界与手动中继房间相同，只是把“人工约定”换成“同队派生”，不构成强认证。开关默认关闭；连接中点“离开房间”会立即断开且本组队不再自动重连（重启助手后该记忆清除）；在空闲面板取消勾选或关闭“自动同步”会立即停止自动连接；队伍解散或客户端离线时约 30／60 秒后自动断开。换一个组队（标识变化）时旧房间先断开再按新标识连接；若新标识被手动离开过、或持续读不到（含接口不提供），旧房间也会断开，不把公开阵容继续发往已离开的队伍。读取不到标识、错过大厅（例如启动时已在选人阶段）时不会自动建房，也不报错打扰；手动加入保持原样。自动连接依赖客户端轮询：关闭“自动同步”后不会触发，已连的自动房间也会在偏好保存或导入备份时关闭。

未验证项：`partyId` 在同一预组队内是否对每台机器一致，仓库没有任何双机实测证据；若不一致，各机会进入不同房间（面板会显示各自的房间码，并在 30 秒后提示“暂时没看到队友”）。`partyId` 在成员变动时是否保持稳定同样未验证。两台 Windows、真实国服组队大厅的验收步骤见[开发指南](development.md)的“真实客户端验收”一节。

## 局域网与互联网的区别

桌面“开黑房间 · 局域网”在用户主动创建／加入后自动分享所选公开阵容与配置。TCP 未加密，六位口令只提供基本加入限制；只在可信局域网或受信虚拟局域网使用。Windows 防火墙应仅允许当前可信网络。虚拟局域网可能不转发 UDP 扫描公告，队友可粘贴房主从对应网卡复制的完整邀请，能否互通仍取决于实际网络。

互联网通道选择“中继”，默认地址为 `wss://room.riftbuddy.dpdns.org`。队友填写同一个地址，约定任意六位数字房间号（例如 `482913`）和另一个六位数字口令；口令只在线下或私聊分享。填写房间昵称后，每人点击加入。新版助手会向默认地址及自定义中继发送公开阵容、个人英雄选择和完整配置分工；只显示实际收到的发送方快照，旧版队友或中继缺失字段时会明确提示，点队友英雄后可另行选择本地参考。采用配置和写入符文由本人点击确认。服务运营者可以看到共享的公开阵容与配置；口令哈希空间很小，不是强认证。地址检查会拒绝明文公网连接、凭据、路径和明显私网字面地址，不验证域名实际解析结果，不能代替选择可信服务。仅本机开发允许 `ws://127.0.0.1`。不能把本机 TCP 邀请填入中继地址。

## 开发者本地验证

先运行仓库的 `pnpm test` 与 `pnpm check`。其中 Worker 测试使用模拟平台对象，只验证所列代码行为。

若已自行准备 Wrangler，可以另外运行本地 Workers 运行时；首次运行可能下载工具，须自行确认环境和网络：

```powershell
# 终端 1，仓库根目录
pnpm exec wrangler dev --config relay/wrangler.toml --port 8787

# 终端 2，仅访问本机
node relay/smoke.mjs ws://127.0.0.1:8787/room/482913 482913
```


弱网冒烟允许用环境变量放宽预算；默认不重试。取值必须为十进制非负整数，非法或超过上界时以 2 退出：

| 变量 | 用途 | 默认 | 上界 |
|---|---|---|---|
| `SMOKE_CONNECT_MS` | 单个成员握手等待毫秒 | 10000 | 2147483647 |
| `SMOKE_SETTLE_MS` | 等待转发帧毫秒 | 6000 | 2147483647 |
| `SMOKE_RETRIES` | 每位成员额外握手尝试次数 | 0 | 100 |
| `SMOKE_RETRY_MS` | 尝试间隔毫秒 | 5000 | 2147483647 |

PowerShell 可先设置 `$env:SMOKE_CONNECT_MS="45000"` 等变量，再运行上述命令。重试仅覆盖 welcome 前握手，沿用同一昵称；旧连接尚未被服务释放时可能收到昵称重复，须给关闭留出间隔。welcome 后掉线、状态丢失或延迟不会因此自动恢复。

作者在 PR 中报告过单条大陆网络的小样本连接与离开延迟；本阶段未独立复核原始网络记录或地址，不能据此确认桌面互联网可用性、所有运营商可达性或游戏实战表现。当前仍只认可明确列出的受控检查。

Wrangler 不是本仓库已安装的开发依赖。未准备工具时，上述命令不会代表本地已验证成功；也不要为运行检查擅自改变账号或部署状态。

## 以后部署时

部署者需自行准备 Cloudflare 账号、Wrangler 与正确的登录环境，检查 `relay/wrangler.toml` 的 Worker 名称和 SQLite Durable Object 绑定。获得部署授权后，在仓库根目录执行：

```powershell
pnpm exec wrangler deploy --config relay/wrangler.toml
```

再使用输出地址进行 WebSocket 冒烟、实际客户端互通和退出清理检查。默认公网地址在 2026-10-12 的单机独立连接复测中，已完整转发二至五人配置、职责与晚加入快照；本次无需更改现有 Worker。没有取得该服务管理权限，不部署、不新建替代服务。两台 Windows、不同运营商及长时连接仍待验证，自有域名也不能保证连通。

Cloudflare 当前允许 Free 计划使用 SQLite Durable Objects，但请求、计算与存储都有额度，超限会失败；不要承诺永久免费或用不完。以[官方计费与额度](https://developers.cloudflare.com/durable-objects/platform/pricing/)、[WebSocket 休眠说明](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)及部署账号的实际计划为准。
