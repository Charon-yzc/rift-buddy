# 战绩详情切换卡顿：调查与修复

用户报告在总览、详尽表格、符文、事件、构建、时间线之间切换后，打开其他局和其他玩家也会卡顿。前一轮只迁移了收藏页，战绩仍在每次状态通知后重建整个应用 DOM。

## 复现证据

`node scripts/smoke-package-match-history.mjs --source --interactions` 使用隔离客户端夹具：20 局、173 条熟练度、36 分钟 × 10 人采样、648 条历史事件。网络和回放写入均模拟，不使用实际账号数据。Electron DevTools CPU profiler 对点击流程采样。

修复前，同一组缓存页签切换的点击处理耗时：事件约 1079ms、构建约 408ms、详尽表格约 140ms。CPU 采样热点为 `disclosure-state` 的后代扫描与属性/可见性读取，其次是整个外壳的 DOM 重建。未操作的另一局卡片与资料区节点均被替换。详情已缓存时，控制器仍发送“开始加载”和“加载结束”两次通知。

早期探针记录的 requestAnimationFrame 等待接近 1 秒，是隐藏窗口的帧调度限制，不能当作可见窗口帧耗时。最终回归使用点击同步耗时与下一事件循环完成的耗时，不以隐藏窗口帧率作为性能结论。

## 修复

- 缓存完整的详情切换只发送一次详情更新，不制造加载状态，不重新请求或计算评分。
- 战绩列表使用预编译的 `HistoryCards.vue`，由 Vue 按对局 ID 复用卡片。详情专用通知只更新战绩列表，不经过整个应用外壳或通用展开状态扫描；未变化卡片 HTML 不写入 DOM。
- 通用展开状态模块跳过 Vue 持有的区域，其展开和焦点由保留的节点管理。
- 被更新卡片的旧 HTML 边界使用 Vue 指令保存和恢复原生 disclosure/控件状态，范围仅为当前卡片。实际雷达玩家选择与事件多选回归先复现了收起/失焦，再验证修复；无关卡片不参与这一步。
- 详情或时间线实际到达后更新左侧总览和完整分析，保留已展开的其他局。账号、筛选、分页、隐私状态变化仍走完整页面更新。
- 等待 Vue 更新后恢复详情页签和表格输入焦点；后台标签的数据返回不抢占当前玩家视图。

修复后同一夹具的源码缓存切换：同步点击约 4–6ms，包含 Vue patch 的下一事件循环约 12–41ms；打开另一局约 27ms，另一位玩家约 39ms。数值是模拟网络下本机观测，不代表实际 LCU/SGP 接口响应时间。

最终 Windows 打包复测同样通过：同步点击约 4–8ms，包含 Vue 更新的下一事件循环约 13–52ms，另一局 29ms，另一位玩家 44ms；未变化的卡片和资料区仍是原节点，雷达选择与事件多选的展开和焦点均保留。完整六页签交互与 `--usage` 500 场/双窗口/断线回归通过，真实客户端写入为 0。全量 `pnpm test` 2603 项，2602 通过、1 项跳过、0 失败；`pnpm check` 检查 682 个 JavaScript 文件及当前资料、图片通过。

## 实际客户端复测（第二轮）

上述夹具没有覆盖真实后台时间线的体量。用户在实际客户端登录后，以隔离用户目录、只读 LCU/SGP 查询和可信输入事件复测（不保存对局、身份或凭据，只记录耗时与采样计数），发现两个问题：

- **构建页为空**：自动来源的第一页改为先读客户端后，时间线也随之走客户端路由。该路由只返回击杀、史诗野怪与建筑事件（约 110 条），没有购买、加点和守卫，10 名玩家的加点与购买批次全部为 0。现在自动第一页的时间线仍取后台完整数据（约 1300 条）；只有用户显式选择客户端来源时才使用客户端路由。后台失败时回退到客户端时间线，并提示部分出装事件可能缺失。
- **展开多张事件卡后所有点击变慢**：真实击杀事件带有逐来源伤害表，单张事件卡约 426 个明细。展开三张后，每次切换页签需要 280–460ms（Event Timing），返回自己需要 432ms。CPU 采样首位是 `Number#toLocaleString`：带选项调用时每次都新建格式化器（约 17µs，缓存后约 0.4µs）。此外，每次详情更新都会重新生成所有卡片的 HTML；卡片内的图表、雷达选择和表格搜索仍会触发整页渲染。

修复：

- `formatNumber` 按精度缓存 `Intl.NumberFormat`。
- 卡片 HTML 按对局、详情状态、页面分析和静态数据缓存，大对象按身份比较。
- 卡片内控件只更新 Vue 卡片列表。
- 事件行和构建块使用 `content-visibility:auto`。

同一实际数据下，展开三张事件卡后的点击降为 37–64ms，打开另一局为 61ms，返回自己为 121–152ms。打开其他玩家时 CPU 空闲，耗时取决于战绩接口响应（121ms–2.45s），本轮未改变。夹具现在为击杀事件生成伤害表并预先展开两张事件卡，预算收紧为同步点击 <120ms、下一事件循环 <300ms。修复前的渲染器在该预算下失败（290–435ms）。

## 第三轮：参照 League Akari

对照本机 League Akari 源码（玩家标签 `v-show` 常驻、详情首次展开才挂载、只挂载当前页签、伤害明细放在悬浮层、卡片 `content-visibility`、按局预取时间线），并在实际客户端复测：

- **连接探测**：每次战绩操作若距上次探测超过 3 秒，都会用 PowerShell 查询客户端进程（约 0.6 秒），即使已读到 lockfile 也会为大区信息执行。现在只要客户端仍能在已知连接上返回当前账号就复用连接；读取失败时重新探测一次，并发读取共享这次探测；探测失败不缓存。打开其他玩家从约 960ms 降到约 230–520ms。
- **未展开的伤害明细和事件地图**：内容放在惰性 `<template>` 中，首次打开时才插入（点击摘要时同步填充，不出现空白帧），卡片状态恢复会逐层展开并恢复嵌套展开状态。展开三张事件卡时页面元素从 3.3–4.7 万降到 1.4–1.5 万。承受/造成伤害两组“按来源 / 目标汇总”原本键名相同而无法恢复，现在按伤害分组区分。
- **玩家标签常驻**：战绩卡片列表按标签放在 Vue `KeepAlive` 中（最多 5 个）。非当前标签的节点移出文档，同一局出现在两个标签中也不会重复元素 ID；返回时重新挂上原节点并保留展开状态。加载中的标签没有卡片列表时保留 Vue 应用而不卸载。后台标签迟到的资料返回不再触发整页渲染。返回自己从约 216ms 降到 112–188ms。
- **时间线预取**：展开一张卡后在后台读取这一局的时间线，同一时间最多一个预取，只占一个请求槽位，不会让用户打开的页面或玩家排在预取之后。预取失败不提示，点开页签时按原流程读取并报告错误；等待预取的页签显示加载状态。停留 2.5 秒后打开事件页为 166ms，原先需要 0.5–2 秒的后台等待。

未采用 Akari 的整页预取（每页约 20 个后台请求，会挤满并发队列并与英雄统计共享后台限额）。

## 第四轮：实时对局加载（含历史阵容演练）

从战绩卡片点击“用本局阵容演练实时对局”后，10 名玩家全部加载完需要约 53 秒，最后一名玩家的段位在 52.5 秒才出现。原因：

- **玩家槽位**：每名玩家（默认同时 2 名）从读取第一页一直占到 20 个详细样本全部读完，后面的玩家连列表和段位都要排队。
- **请求排队**：116 个后台时间线和 25 个分页请求共用战绩服务的 3 个并发槽位。
- **整页重绘**：每批数据都触发一次整页重绘，展开状态扫描对每个展开区重新遍历整张玩家卡片（约 2000 个元素）。

修复：

- **玩家槽位**：只覆盖第一页和段位。较深分页（第 21–50 局）合并为一次请求，转入后台队列。
- **后台队列**：较深分页和详细样本共用一个后台队列，所有玩家共享。较深分页优先；样本按轮次读取，每名玩家先得到第 1 个样本，再轮到第 2 个。有玩家的第一页未读完时，后台只运行 1 个请求；之后运行 2 个，留一个槽位给用户打开的战绩页。
- **共同对局只读一次**：同一局出现在多名玩家的历史中（开黑队友、被演练的那一局）时，本次阵容内只读取一次。
- **精简时间线**：样本只保留分析读取的字段（帧位置、等级、补刀、伤害，以及击杀和史诗野怪事件），总事件数单独保留。新增测试断言分析结果与完整时间线逐字段一致。
- **页面重绘**：实时对局页最多每 150ms 重绘一次，最后一次变化一定绘制。展开状态扫描在同一轮中对每个容器的控件和标题只读取一次。

同一客户端上的实测（隔离用户目录、只读查询，只记录耗时和计数）：

| 指标 | 修复前 | 修复后（3 次） |
| --- | --- | --- |
| 10 名玩家段位全部出现 | 52.5 秒 | 5.1–5.8 秒 |
| 全部加载完成 | 52.8 秒 | 27.9–54.8 秒 |
| 时间线请求 | 116 个 | 73–87 个 |
| 分页请求 | 25 个 | 19 个 |

全部完成时间主要取决于后台时间线响应：三次实测的平均耗时分别为 0.29、1.05 和 0.51 秒，0.51 秒那次全部完成用时 30.9 秒。修复前每张卡片要等前面的玩家读完样本才开始；现在列表和段位在约 5 秒内全部出现，样本随后逐轮补齐。渲染进程的忙碌采样从约 1.19 万降到 0.60–0.88 万。展开状态扫描曾占重绘时间的 78%，现在约占三分之一。剩余的重绘成本主要是约 2.2 万个元素的 HTML 解析和布局，要进一步降低，需要把玩家卡片迁到 Vue 并按卡片更新。
