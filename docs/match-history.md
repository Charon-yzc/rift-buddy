# 战绩查询

本模块移植并适配本机提供的 League Akari 1.5.1 战绩相关源码，来源提交 `60f1584c3d3e45b2bb183aefcc615d35d7cffcb8`。版权声明见 `THIRD_PARTY_NOTICES.md`。

## 使用

1. 登录英雄联盟客户端，在开黑搭子完成连接（读取是自动的，不需要先授权）；客户端以管理员身份运行时，Windows 可能要求一次权限确认，确认后继续。
2. 左侧选择“战绩查询”，点击“我的战绩”，或输入玩家的完整 `游戏名字#标签`。只输入名字时尝试 Riot Client 名字搜索，并从结果中选择玩家。
3. 默认自动选择游戏后台；同区后台不可用时回退到本机客户端。可明确选择客户端或游戏后台，以及目标大区。跨区能力依赖具体游戏后台接口及认证，失败不会使用本区数据冒充结果。
4. 每页默认 20 局，可改为 10 / 50 / 100 局，并使用首页、上一页、下一页与页码跳转。普通批量每轮至多 20 局，单个标签最多保留 500 局。按英雄、分路或全部筛选收集时从第一页重新扫描，最多扫描 500 局，只保留匹配结果，分别显示扫描数与匹配数。
5. 列表按紧凑玩家行排列：主列自上而下是英雄、召唤师技能、符文、KDA/伤害/补刀，以及结果、装备、队列与时长；右侧是阵容缩略图（斗魂等多小队对局显示队伍人数摘要）。行尾箭头下拉展开本局详情，展开后在本局卡片内切换总览 / 详尽表格 / 符文 / 事件 / 构建 / 时间线，可用键盘左右方向键切换。窗口较窄时，分页、队列、筛选和总览收进可折叠区，优先显示对局卡。
6. 装备、符文、属性碎片、强化、召唤师技能、英雄和 KDA/伤害数值都可以悬停查看详情浮层（状态格与标签同时可用键盘聚焦）：装备显示价格、合成路径与效果，符文显示说明和本局实际记录，统计与事件显示字段和可用性。浮层使用顶层弹出层，不会被卡片滚动裁剪，并在窗口边缘自动换向；历史版本的效果会与随包资料版本一起说明。购买、加点、完整属性和阵亡伤害仅在数据源实际返回时展示，LCU 常缺少其中部分事件。时间线同时展示对局结束后的目标统计；满足公开数据条件时展示带说明的打野分钟位置参考。
7. 排位与熟练度在当前大区按需读取，挑战成就按点击从后台读取。展开本局后在队伍表里点击玩家名字、或点击近期共同对局标签打开标签；同一玩家与大区复用已有标签，Ctrl 点击支持后台打开，最多 10 个。查询工具提供本次运行备注与隐私展示。
8. 回放检查、下载和观看都由用户点击发起；只允许当前大区已加载对局，下载和播放只在大厅或结算阶段。首次检查没有元数据时，按 Akari 的接口流程尝试初始化；过期、版本不兼容或接口拒绝会显示错误。点击后仅轮询只读进度，最多 120 次，不重复发起下载或观看。
9. 高级筛选可视化编辑嵌套 AND / OR / NOT 与同一玩家范围，支持实际值、队伍/全场占比、装备数量与槽位；保留 JSON 导入导出。日期快捷条件和最多 12 个命名筛选预设仅存本次运行内存。
10. “完整战绩分析”展示原始 Akari 引擎的胜负、KDA 波动、英雄/分路、技能、队伍侧、参考评分和历史打野分析；可点击补齐最近 20 局时间线。时间线支持单人、双人、差值、多玩家和已知队员平均曲线，以及逐分钟属性与真实坐标。

## 实时对局

主导航“实时对局”按大厅、英雄选择、游戏中和结算阶段读取公开成员，默认每 5 秒同步成员。每位玩家分别加载战绩、资料和历史时间线；慢查询不会暂停成员同步，关闭页面停止轮询，旧阶段与旧成员请求不能写入新状态。

卡片显示公开英雄与预选/锁定状态、位置与补位信息、排位、近期战绩、常用英雄/熟练度、历史表现标签、历史打野采样和本次运行相遇记录。支持全队/单人刷新、排序、样本数、并发、数据源、队列、标签与隐私设置。队伍统计汇总已加载的玩家历史，不代表本局胜率；共同对局分组标为历史推断。

版式沿用 Akari 的对局面板：队伍头部是阵营色点、粗体队名、队伍平均胜率 / KDA 与共同对局标签（悬停列出该组成员，并注明是历史推断）；玩家卡固定 240px 宽，列间距 4px，宽队伍横向滚动。卡片自上而下是圆形英雄头像与等级、名字、排位行、胜率 / KDA / 位置三格、标签、常用英雄与近期战绩。

悬停或键盘聚焦任一格子都会打开顶层详情：排位表格（队列、段位、胜败、最高、上赛季）、胜率样本与连胜连败、KDA 变异系数、位置（当前 / 主选 / 副选 / 补位原因 + 历史分路次数）、单个英雄的历史样本、单局摘要（时间、时长、KDA、分均补刀、伤害占比）与共同对局成员。浮层不会被卡片滚动裁剪，并在窗口边缘自动换向。

选人中的隐藏身份保留空卡，不解析 obfuscated 身份、不从历史猜测。游戏后台 GSM 补充仅用于与当前游戏 ID 一致的进行中快照，凭据和连接参数不进入页面或缓存。已结束对局可进入历史阵容演练，显式标识为历史保留，点击返回当前对局后恢复同步。

## 数据口径

- 缺失统计显示“未读取”，已确认的 0 保留为 0。LCU 没有的分路、护盾、强化或时间线字段不从其他数据猜测。
- 近期统计过滤人机/非匹配对局、重开和中止，只统计已经确认本人参与且胜负可知的局。筛选后样本数会单独说明。
- 斗魂竞技场使用已返回的小队数量和名次，将前半小队视为胜利；实际名次同时保留显示。
- 依赖完整队伍的占比和评分只在逐队人数核验通过后计算，包括 1750 队列的三人小队。未补齐的摘要不冒充完整队伍。
- Akari 参考评分使用其击杀参与、伤害、承伤、经济、治疗、视野、补刀和胜率权重，总分 17；资料不足时显示“资料不足”。这不是官方评分，也不是最优阵容或获胜概率。
- 共同对局仅说明已加载对局里同队/对手的重复出现，不等于预组队关系。
- 打野路线使用已结束对局的分钟位置和击杀参与事件。区域权重、营地距离参考沿用 Akari；一分钟位置接近某营地不能证明实际首开，不提供游戏中的追踪。

## 实现与边界

`src/core/match-history/` 负责清洗和筛选；`src/core/akari/` 固定原始纯分析引擎与适配层，保留完整 MIT、源文件指纹和可重现生成脚本。`services/match-history.mjs` 负责查询对象、会话检查和缓存；`services/match-history-{routes,sgp,riot}.mjs` 分别限制 LCU 路由、固定 SGP 地址和 Riot Client 回环名字搜索。个人战绩、备注、相遇和筛选预设只在独立控制器内存中保存，不写入收藏、偏好或备份；仅无身份的实时展示设置可持久化。

LCU/RC Basic 凭据只发送到本机回环。后台战绩使用 entitlements access token，玩家大区资料使用 league-session token；凭据不通过渲染层、不写入日志、不发送到项目服务器。固定后台请求不跟随重定向，单次响应上限 8 MB；本机 LCU 保留 2 MB 上限；授权管道为战绩单独设置 4 MB 字符上限，其他操作仍是原上限。

每个服务最多同时执行 3 个战绩操作，队列最多 12 个；单页最多 100 局；服务缓存最多 128 条且不超过估算 48 MB，玩家句柄最多 48 个。实时历史总量最多 2,000 份玩家对局，时间线临时内存不超过估算 48 MB，单玩家默认 50 局、详细 20 局、并发 2，设置有上限。账号或连接身份变化后旧句柄失效；页面请求用世代号防止旧结果覆盖新查询。所有自动化测试中的客户端和回放写入均为模拟。

列表仅传卡片与分析所需字段；227 项公开统计白名单在显式展开单局详情时读取，避免大页穿过授权管道时无界膨胀。时间线分别保留事件列表是否提供、助攻列表是否提供；缺少事件不等于确认零事件，缺少助攻不作为单人目标证据。竞技场的隐藏槽位保留原始传输队伍身份，相遇队友/对手只使用可验证的小队标识，否则显示关系未读取。

同区列表、详情或时间线后台失败时可退回 LCU，并说明减少的字段；跨区不回退。并发缓存按来源合并，清理直接使旧查询失效，无需等待查询队列。窗口缩窄时近期统计改为可展开区，保留常用英雄及共同对局入口。

SGP 为未公开且会变化的接口。地址参考固定的 Akari 配置，不宣称永久有效或所有大区互通。网络加速器可能只代理客户端而不代理助手的 SGP 请求；可在同区切换为“客户端”确认数据源差异。

## 验证

执行 `pnpm test`、`pnpm check`，再打包并运行 `node scripts/inspect-package.mjs --verify-current`、`node scripts/smoke-package-lifecycle.mjs` 与 `node scripts/smoke-package-match-history.mjs`。战绩冒烟使用隔离设置和模拟 loopback 数据，覆盖页面查询、分页、筛选、详情、符文、出装、时间线、回放点击和断线错误，以及桌面/小屏截图。

真实国服验收仍需与已登录客户端逐项核对本人、战绩、KDA、装备、分页、回放与后台大区支持；模拟与打包通过不能替代该项验证。
