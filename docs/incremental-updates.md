# 增量更新与安装替换

0.56.0 的安装目录新增 `rift-buddy-install.json`，记录程序文件的大小和 SHA-256。后续更新可复用完全一致的运行库，只下载变更文件。0.55.1 及更早客户端没有此功能，首次升级必须使用完整安装包。

## 玩家看到的行为

- 有匹配增量且本机文件完整时，优先下载增量包；元数据缺失、文件修改、下载损坏时回退完整包。
- 点击安装后再次核验基线。安装器先把变更与可复用文件拼齐，校验所有新版文件，然后停止实际安装路径下的应用进程并运行旧卸载器，最后安装新版。
- 收藏、个人配置、配色与其他玩家资料在用户数据目录中保留。安装目录中的额外用户文件也不主动删除；新版路径与用户文件冲突时安全失败，不覆盖用户文件。
- 安装复制失败时逐项恢复旧文件、卸载登记和快捷方式。不能完整恢复时保留安装目录旁的独立恢复备份，并在错误中给出路径。
- 没有可用增量或变更过大时使用完整包；增量不保证每次都更小。它是逐文件差量，并非压缩文件内部的二进制块差量。

## 构建与发布

1. 运行测试和检查，生成并验收完整包。保留上次发布的安装清单。
2. `pnpm installer:delta --base=上次清单的绝对路径`。它校验当前打包目录，对比文件内容，生成 `RiftBuddy-新版-From-旧版-Update.exe` 与 `RiftBuddy-新版-Delta.json`，将哈希加入同版校验清单。
3. 增量超过 90 MiB、复用不足或基线不合适时，构建拒绝生成，继续发布完整包。构建需要 Windows 原生 NSIS，必要时设置 `RIFT_BUDDY_MAKENSIS`。
4. GitHub 与 Gitee 上传相同增量字节。先上传安装文件和校验清单，再上传增量描述，完整包镜像清单最后上传。不能用尚未上传的描述宣称镜像同步完成。
5. 保留原有完整包回退、双渠道下载与 SHA-256 验证要求；历史 release 不删除。仅当用户要求发布安装包时才执行上传。

## 验证

`tests/incremental-update.test.mjs` 使用本地合成下载，检查增量选择、修改基线、损坏回退与路径清单。`scripts/smoke-installer-upgrade.mjs` 使用独立目录、注册表身份和快捷方式，实际运行 NSIS 安装/卸载，覆盖全量与增量、进程停止、用户路径冲突、文件锁回滚和旧卸载器兼容。不会安装到玩家当前程序目录。

技术调研参考 [electron-builder 的差量更新说明](https://www.electron.build/v26/docs/nsis/) 和 [NSIS 卸载等待说明](https://nsis.sourceforge.io/When_I_use_ExecWait_uninstaller.exe_it_doesn%27t_wait_for_the_uninstaller%3F)。项目继续使用现有原生 NSIS 打包流程。
