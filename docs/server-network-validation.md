# 反馈服务与房间连接验证

2026-10-23 在已核验的 A 机（ARM64，实例身份见本地 `rift-buddy-servers.json`）补测了 Rust 反馈服务的传输边界，并从 Windows 原生 Node.js 24.19.0 测试了客户端的实际网络路径。结果显示反馈接收限制及房间基础交互可用；本次未更改正式服务或客户端的连接策略。

## ARM64 反馈边界

使用正式部署的 `rust-9b3bddd5/rift-buddy-feedback` 二进制，以反馈服务用户运行独立进程。每项测试使用自动分配的回环端口和独立临时目录，不读取或写入正式反馈目录，不占用正式提交配额。

| 测试 | 实测结果 |
| --- | --- |
| PNG、字段白名单、文件权限 | PNG 正常落盘；未知字段剥除；目录 0700、文件 0600 |
| 分块请求 | 拆成多个 chunk 的 JSON 正常接收 |
| 请求体上限 | 声明长度及实际 chunked 流量超过 14 MiB 均返回 413 |
| 两个进行中请求及断线 | 第三个提交返回 429；前两个断线后名额恢复 |
| 慢请求头 | 不完整头部在 5.002 秒关闭 |
| 慢请求体 | 不完整请求体在 20.002 秒返回 408；名额恢复 |
| 请求头上限 | 超限完整头部返回 431，随后健康检查正常 |
| 总连接上限 | 16 条不完整连接占用期间，第 17 条关闭；断线后恢复 |
| 磁盘配额 | 200 条及 256 MiB 上限分别返回 503；容量夹具使用稀疏文件 |
| 过期清理 | 八天前的 UUID 记录删除；当前记录及非记录文件保留 |
| 符号链接 | 链接目录及 UUID 链接记录导致启动拒绝，链接目标保持完整 |
| 有请求时退出 | SIGTERM 后 8.037 秒内退出，符合十秒 systemd 停止期限 |

合计 12 项通过、0 项失败。临时进程、合成记录及上传的测试脚本已清理。正式服务本次检查时 `NRestarts=0`。该套件尚未注入停滞的 fsync，也未证明 Node 与 Hyper 对每一个原始头部字节的计算完全一致。

复现脚本为 `scripts/check-feedback-transport-remote.py`，需先核对顶部二进制路径和实例身份，再以反馈服务用户运行。测试最多保留 16 条隔离连接，并串行执行约二十秒的接收超时用例；不对正式端口施加该负载。

## 客户端 HTTPS

反馈客户端 `services/feedback.mjs` 使用 `https.request(..., {agent:false})`。本次以相同 Node HTTPS API 请求公开反馈入口的 GET，预期 405，不提交反馈。对照组采用单连接 `https.Agent({keepAlive:true,maxSockets:1,maxFreeSockets:1})`，仅存在于测试脚本。

| 方式 | 样本 | 总耗时 |
| --- | --- | --- |
| 当前客户端方式，每次新建连接 | 4 | 1819.59、1832.43、2335.99、2406.57 ms |
| 候选连接池首次请求 | 1 | 1835.42 ms |
| 候选连接池已复用连接 | 3 | 538.82、539.89、541.79 ms |
| 独立空闲测试，连接空闲 31 秒后复用 | 1 | 634.11 ms，`reusedSocket=true` |

反馈客户端有三十秒的发送间隔，因此另测了 31 秒空闲后复用，避免只用连续请求夸大实际收益。该单次结果只说明当前网络路径下连接当时仍可复用，不能保证所有空闲时长、运营商或网络转发环境都相同。GET 不包含 POST 上传、图片处理或服务端 fsync 耗时。Node 报告的连接阶段还可能包含系统级网络转发，不能直接等同于到悉尼服务器的物理 RTT。

## 房间交互

使用 `services/room.mjs` 和 Node 原生 WebSocket；测试创建随机房间与合成昵称，发送的仅是合成公开英雄选择。没有传入本机账号、真实英雄统计、比赛或凭据，结束时关闭自己的连接。

| 交互 | 样本及耗时 |
| --- | --- |
| 完整入房 | 3 次：2414.68、2453.81、2950.09 ms |
| WebSocket 打开至 welcome | 3 次：549.65、570.38、580.44 ms |
| 心跳往返 | 9 次：546.15～602.65 ms |
| 双成员入房及双方看到成员 | 1 次：2494.46 ms |
| 阵容 A → B / B → A | 各 1 次：561.14 / 562.42 ms |
| 离开通知 | 1 次：550.44 ms |
| 保持连接及自动心跳 | 35 秒，未自发重连 |
| 主动关闭测试 socket 后自动重连 | 1 次：3916.95 ms，自己的阵容保留 |

心跳计时先等待客户端入房时自动发送的首个 pong，再逐次发送手工 ping，并直接在 message 回调取时，避免把残留 pong 误算成新请求的快速响应。成员和阵容检测使用二十毫秒轮询，因此相关数字包含最多约一个轮询周期的检测误差。

自动重连测试使用可控 socket 关闭，不等同于断网、丢包或黑洞链路的完整恢复测试。测试只保持 35 秒，未验证长期稳定性、十二人同时广播或完整大方案的公网表现。房间中继仍是 Node 实现，此处不能据此归因 Rust 的收益。

复现：`node scripts/check-room-network.mjs`；仅测空闲 HTTPS 复用可用 `node scripts/check-room-network.mjs --https-only --idle-probe`。这些脚本会访问现有公开服务，请保持有界执行。
