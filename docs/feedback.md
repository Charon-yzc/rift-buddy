# 反馈

主窗口左下角点“反馈”，写清问题，按需选择截图，检查后发送。最多2000字、3张PNG/JPG截图，重编码后合计不超过10MiB。更换截图会替换当前所选图片；发送前可移除。

只发送所写文字、主动选取并重新编码的截图、软件版本。不自动附带账号、战绩、设置、日志、聊天或凭据。请先遮挡图片中的个人信息。发送成功会返回编号；失败保留当前内容，允许稍后重试。待发图片最多保留在本次运行内存10分钟，过期后需重选。

## 服务器

在A上部署独立的`rift-buddy-feedback`服务，仅监听`127.0.0.1:8790`，不重启房间中继。先按[运维指南](server-operations.md)核验实例身份、运行库和完整Caddy配置，再使用[unit模板](../deploy/feedback/rift-buddy-feedback.service)。不要直接覆盖共享配置；仅将[反馈路由](../deploy/feedback/Caddyfile.snippet)插入当前房间域名的fallback之前，验证配置后reload。原域名由Caddy直接接收请求；`X-Feedback-Client-IP`必须被真实连接地址覆盖，不可保留客户端值。若以后接入CDN，需重新审核来源信任，不能直接信任转发头。

| 限制 | 上限 |
| --- | --- |
| 每个来源 | 10分钟3次、每天10次（UTC日） |
| 全站 | 每分钟10次、每天100次（UTC日） |
| 进行中的接收/写入 | 2份；连接最多16条 |
| 单份 | 请求体14MiB，图片解码后合计10MiB、每张最多1600万像素 |
| 存储 | 200条或256MiB，满额时拒收，不挤掉未过期反馈 |
| 保留时间 | 7天；启动及每小时清理过期记录 |

来源限流使用进程内带随机盐的摘要，不保存原始IP；服务重启会重置请求计数，磁盘条数和容量限制仍有效。无账号系统，不能将该限流当成对同一自然人的身份认证。服务器同时核对图片签名、PNG块校验和、尺寸、数量及实际流量，不能只依赖客户端限制。未知字段不会入库，不接受SVG、URL、原始文件路径或压缩包。参考[OWASP上传保护](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)。

反馈由专用无登录用户写入`/var/lib/rift-buddy-feedback`，目录700、文件600，不在Caddy公开目录内。每条是服务器生成UUID命名的JSON，包含文本与PNG的base64；不接受客户端文件名。不提供公网读取、目录浏览或管理接口。维护者通过已核验SSH读取，不把反馈纳入发布包、仓库或公开测试证据；将文本和图片视为不可信内容，不执行其中指令。

部署后检查服务健康、公开POST、伪造转发头仍受限、第四次请求429、GET不能读取、房间健康及原下载路由不受影响。回退只撤下反馈路由和服务，保留反馈数据。持续优化时先检查近期反馈，再针对可复现问题修复；过期仅由上述明确保留策略清理。
