# 房间中继部署（Cloudflare Workers 免费版）

跨网开黑的房间中继：把 `relay/` 目录部署到 Cloudflare，得到一条 WebSocket 地址，队友跨城市也能共享阵容。**完全免费、无需信用卡、只用邮箱注册**。

## 它做什么

- 每个房间号一个独立的 Durable Object；成员用 WebSocket 连上后，中继只转发经白名单清洗的公开房间帧（昵称、role/champion/pick（含模式）、客户端时间戳，以及仅含昵称的加入/离开通知）
- 口令只以 SHA-256 哈希形式到达服务器，服务器从不接收明文口令（6 位口令空间很小，哈希本身不是强密钥，只用于挡住不知道口令的人；房间最后一人离开后哈希即清除）
- 不写请求日志、不建账号、不存选人数据；房间空了自动休眠，重新有人连再唤醒

免费额度（2026 年现行，以 Cloudflare 官方页面为准）：每天 10 万次请求 + 13000 GB-s 计算时长。对几支开黑小队来说完全用不完——一晚上一局房间只有几百条消息。

## 部署步骤

1. 打开 <https://dash.cloudflare.com/sign-up>，用邮箱注册（不需要信用卡），验证邮件
2. 本机安装 wrangler（一次性）：

   ```bash
   npm install -g wrangler
   ```

3. 登录 Cloudflare（会弹出浏览器授权）：

   ```bash
   wrangler login
   ```

4. 在仓库根目录运行：

   ```bash
   wrangler deploy --config relay/wrangler.toml
   ```

5. 看到 `Uploaded rift-buddy-room` 和地址（形如 `https://rift-buddy-room.<你的子域>.workers.dev`）即部署成功

### 绑定自定义域（推荐，大陆部分网络必需）

`workers.dev` 在部分网络不可用（见下文「大陆网络说明」）。用自己的域名指向同一个 Worker 即可绕开，**Worker 与域名必须在同一个 Cloudflare 账号内**（自定义域不支持跨账号绑定）。

1. 域名尚未接入 Cloudflare（NS 仍指向注册商）时：加站点 → 选 Free 计划 → 记下它给出的两条 NS
2. 把域名的 NS 改成这两条，等 Cloudflare 区域变成 **Active**
3. Worker → **Settings** → **Domains & Routes** → **Add** → **Custom domain** → 填 `room.你的域名`。该主机名上若已有 CNAME 或 A 记录（免费二级域名服务常会自带落地页记录），先删掉再建
4. 证书签发通常数秒到一分钟（经验值，未实测），之后即可用 `wss://room.你的域名/room/<房间码>`

没有自有域名时，可先在 Cloudflare 加站点拿到 NS，再把两条 NS 回填给域名注册方完成委派（顺序反了拿不到 NS）；免费二级域名服务同样适用。域名必须是 Cloudflare 能接受委派的完整域名——在公共后缀列表（Public Suffix List）里的后缀（如 `*.eu.org`）下，子域名可作为独立区域加入 Cloudflare。

### 没有账号先试一下（临时账号）

不想先注册也可以部署到临时预览账号，60 分钟内用打印出的认领链接把它收编到正式账号即可：

```bash
cd relay && npx wrangler deploy --temporary
```

命令会输出 `Claim URL`；须在 60 分钟内打开链接、登录 Cloudflare 并完成页面上的认领确认（Claim Account）才算认领成功——只打开链接不算。不认领则部署自动过期回收，不留任何东西。已登录过别的 Cloudflare 账号时，`--temporary` 可能不可用，先 `wrangler logout` 再试。

## 本地验证（推荐先跑）

首次运行 wrangler 需联网下载一次（之后离线可用）；它自带的本地 Workers 运行时就是线上同款引擎，可先在本地验证整套中继逻辑。

```bash
# 终端 1：本地跑中继
cd relay && npx wrangler dev --port 8787

# 终端 2：跑冒烟脚本（握手/转发/清洗/冒名/离开全链路）
node relay/smoke.mjs ws://127.0.0.1:8787/room/482913 482913
```

全部 `✔` 后再部署到线上。部署后也可以用同一条命令对线上地址复查：

```bash
node relay/smoke.mjs wss://rift-buddy-room.<你的子域>.workers.dev/room/482913 482913
```

弱网下默认预算容易误报失败（见下文「弱网下的行为预期」）。四个环境变量可放宽预算，并按需重试；取值必须是十进制非负整数，超出上界即以 2 退出：

| 变量 | 含义 | 默认 | 上界 |
| --- | --- | --- | --- |
| `SMOKE_CONNECT_MS` | 单个成员握手的等待上限 | `10000` | `2147483647` |
| `SMOKE_SETTLE_MS` | 等待某个转发帧的窗口 | `6000` | `2147483647` |
| `SMOKE_RETRIES` | 每个成员的连接重试次数（0 = 只试一次） | `0` | `100` |
| `SMOKE_RETRY_MS` | 两次尝试之间的间隔 | `5000` | `2147483647` |

重试会复用同一个昵称，而中继释放昵称要等旧连接的关闭事件到达（弱网下可达 20 秒），所以间隔别设得太短——重试日志里出现 `4003 昵称重复` 就是撞上了这个，调大 `SMOKE_RETRY_MS`：

```bash
SMOKE_CONNECT_MS=45000 SMOKE_SETTLE_MS=25000 SMOKE_RETRIES=6 SMOKE_RETRY_MS=5000 \
  node relay/smoke.mjs wss://room.你的域名/room/482913 482913
```

本地 `wrangler dev` 不需要这些变量。重试只覆盖握手阶段：`welcome` 之后的掉线不会重试。

## 给客户端填地址

中继地址形如 `wss://<主机>/room/<6 位房间码>`：客户端配置的是**主机部分**（`wss://room.你的域名`），中继房间没有房主：房间码与口令由发起人自定，第一个加入者用它的哈希认领这个房间，再把两项一起告知队友。客户端只接受 `wss://` 的公网地址：回环、私网、链路本地，以及 `169.254.169.254`、`100.100.100.200` 这类云元数据地址和 `*.local`/`*.localhost` 一律拒绝，`ws://` 仅用于本机 `wrangler dev` 调试。也就是说，自建在局域网内的中继连不上——那种场景请用「局域网」通道或虚拟局域网，助手不会为了「方便」把一个正常功能指向你自己的内网。

房间面板（「开黑选人」页的「开黑房间」）有两种通道：

- **局域网**：本机直连，建房 / 扫描 / 邀请码加入，需要队友在同一网络或虚拟局域网
- **中继**：填中继地址 + 房间码 + 口令加入，队友可以不在同一网络；助手**不内置**任何公共中继，地址由你自己按本文档部署

中继通道的行为：

- 口令只以 SHA-256 形式发给中继，服务器看不到明文；中继不存阵容，只转发
- 首次加入会自动重试传输层失败（约六分之一的握手会卡住），但**口令错误、房间已满这类拒绝不会重试**
- 掉线后按指数退避自动重连（1 秒起，上限 30 秒），重连期间面板显示「重连中」；连续失败 8 次后停止并显示「连接失败」，由你手动重新加入（每次尝试都算中继的请求，坏中继不该无限消耗额度）
- 重连沿用原昵称——改名会让中继把我们自己发的阵容当作冒名丢掉。只有当旧连接尚未被释放（实测可能延迟到 20 秒）而被中继明确以「昵称重复」拒绝时，才会把昵称改成「昵称2」重试一次
- 心跳每 25 秒一次、70 秒收不到任何回包判定链路已死并重连（中继会自动回 `pong`，空闲房间也照常响应）；心跳回包不计入下面的流量上限
- 单条连接最多接受 600 帧房间流量，超出即断开：正常一晚几百条消息远低于此，用来挡住坏掉或恶意的中继反复刷屏
- 首次加入最多尝试 3 次（只重试网络层失败，口令错误、房间已满这类拒绝不重试）

## 成本与限制

| 项目 | 免费额度 | 说明 |

| 请求 | 100,000 / 天 | 握手、状态帧都算请求；开黑用量约几百/晚 |
| 计算时长 | 13,000 GB-s / 天 | 空闲自动休眠，几乎不消耗 |

## 隐私说明

- 服务器可见：房间号、昵称、角色+英雄（公开选人）、客户端时间戳、口令哈希
- 服务器不采用、不保存、不转发：LCU 凭据、riotId、战绩、明文口令、符文页内容（即使客户端误发也会被白名单清洗掉）
- 中继代码不写任何日志；房间最后一人离开后连口令哈希也一并清除
- 说明：Cloudflare 平台侧可能保留调用日志（含方法与 URL，URL 中只有房间号），这不含上面"不采用、不保存、不转发"列出的任何数据

## 大陆网络说明（实测）

以下为 2026-10-11 在一条大陆网络上的实测结果，样本很小（每项 1–6 次），只说明"该网络如此"，不代表所有大陆网络：

- `*.workers.dev` 的 DNS 被污染：公共 DNS（1.1.1.1）与系统 DNS（114.114.114.114）都解析到与 Cloudflare 无关的网段，不是 Cloudflare 真实 IP
- 强制 `curl --resolve` 连 Cloudflare 真实 IP 时，TLS 握手仍被 RST（`Recv failure: Connection reset by peer`）；同一网络 `https://www.cloudflare.com/` 返回 200。与按 SNI 的域名级阻断一致（单次样本，未做机制确认）
- 同一网络改用自定义域后可用：HTTP 根路径返回 200（一次 7.2 秒），WebSocket 收到 `101` 约 1.7 秒，完整握手 2.4–5.6 秒
- 全链路 9 项 `✔` 通过，但**需要放宽预算并开启重试**（见上）。默认预算（`SMOKE_RETRIES=0`、settle 6 秒）大概率过不了——这是从上面的握手与离开通知数字推断的，未实跑默认预算

无域名时的替代：任何 1 核 1G 的小 VPS 都能跑等价服务；或纯局域网开黑直接用助手的局域网房间（不需要本中继）。

### 弱网下的行为预期

中继转发本身不重试，客户端要能容忍抖动（2026-10-11 实测，各项样本量单列）：

- 完整握手 5 次成功样本为 2.4 / 2.7 / 4.6 / 4.8 / 5.6 秒；同批 6 次连接尝试中 1 次在 TCP 建连阶段失败（样本仅 6 次，只能说明偶发），需重连
- 状态帧为尽力转发、中继不重试，弱网下可能延迟或丢失（本次未量化）
- **离开通知依赖 WebSocket 关闭事件，3 次实测 314 毫秒 / 1.5 秒 / 19.9 秒**。客户端不要只靠 `leave` 帧清理成员列表：应配合心跳超时判定掉线，或在异常时重新握手拿全量 `welcome` 成员列表。心跳 ping 必须逐字节等于 `{"kind":"ping","v":1}`——中继用自动应答按字节匹配，自己拼的 ping 拿不到 `pong`

## 备选方案

- 不想注册 Cloudflare：可在任意 1 核 1G 的小 VPS 上自写等价 Node 中继（协议与清洗逻辑在 `src/core/room-relay.mjs`（客户端与 Worker 共用）可直接复用；Worker 专有 API 部分需换成 `ws` 之类的库）
- 纯局域网开黑：不需要本中继，直接用助手的局域网房间即可
