# 视频资料采集与笔记流程

本流程用于把公开游戏视频整理成可追溯的项目研究资料。先确认取得了什么内容，再编写笔记；只有标题、搜索摘要或第三方索引时，记录为候选，不能声称已经观看、转写或完成视频分析。

流程整理自用户指定的两条 Notion 技能：[Notion 视频笔记规范](https://www.notion.so/4009af9812d6818e9ad4e8dac917e39f)与[本地提取 YouTube 视频内容（无字幕时）](https://www.notion.so/4009af9812d681e9aa3aed34a8250324)。下文保留其笔记结构与无字幕处理方法，并补充项目中的状态记录、版本核验和交付要求。阅读本页即可执行，不依赖对私有 Notion 页的访问。

## 1. 固定频道、时间窗和目标版本

1. 在原站核验频道 handle、channel ID、每条视频的 uploader；同名账号或站外索引只能提供线索。无法核验的字段保留未知。
2. 把“最近一周”等相对范围固定为带时区的起止时间，明确起点包含、终点不包含。查询分页直至覆盖整个时间窗，保留枚举来源与缺口。不能把“最新 9 条”写成“一周全部”。
3. 保存视频 ID、规范原链接、精确发布时间、时长、频道、播放量与点赞的读取时间、字幕状态、章节和许可。缺失值用 `null`，不能从相对日期推断精确时间。
4. 记录项目基线完整提交 SHA、`data/game.json` 中的补丁版本，以及视频实际录制补丁和判断依据。上传日期、标题“4.0”、项目目录名都不能证明录像属于同一 LoL 补丁。

每批使用独立目录，例如：

```text
docs/research/hex-<补丁>/<频道>/<起始日期>_<结束日期>/
  README.md          # 范围、覆盖缺口、实际进度及逐条入口
  manifest.json      # 来源、元信息、状态、阻塞原因、笔记相对路径
  pending/<ID>.md    # 尚未完成笔记的候选／采集记录
  notes/<ID>.md      # 已有内容依据并完成整理的笔记
.local/video-research/<批次>/<ID>/
  ...               # 本地原始媒体、字幕、转写、关键帧与提取记录
```

原始媒体与临时产物使用已被 Git 忽略的 `.local/`，不得夹带浏览器配置、Cookie、账号会话或客户端资料。归档文件以视频 ID 命名，避免重名、中文标题变动和路径字符问题。

## 2. 分别验证访问路径

先对预期服务做一次只读访问检查，再选择可用提取方式。不要把历史机器上的失败结论套用到所有环境，也不要在同一种错误下反复下载。

| 实际观察 | 可以得出的结论 | 后续动作 |
| --- | --- | --- |
| 原站页面、字幕或媒体确实可读 | 对应访问路径可用 | 核验来源后采集，记录实际取得的文件 |
| `CONNECT tunnel failed: 403 Forbidden` | 代理建立连接失败，还没进入目标页面 | 记录域名、工具、时间与错误；检查环境网络配置，不断言为 YouTube 未登录或验证码 |
| 网页工具报 `Online fetch throttled` | 该工具未读取到页面正文 | 保留失败状态；搜索结果或第三方索引不能替代视频内容 |
| 播放器明确提示字幕不可用 | 该视频在本次检查中没有可用字幕 | 可播放且具备录制条件时走无字幕流程 |
| 仅字幕请求失败 | 字幕是否存在仍未知 | 不标为“无字幕”，先查失败原因 |
| 原电脑的 Chrome 未接入当前任务 | 不能使用原电脑登录态 | 使用已获授权的可用环境，或等待用户提供可读取文件 |

环境配置显示“不受限”不等于每个域名已经通过实际请求。分别报告命令行、网页工具、实际浏览器的结果；只在确实检查过浏览器时声称浏览器可用或不可用。保留现有代理与 TLS 校验，不绕过平台限制，不提取登录凭据。

## 3. 优先取得已有字幕与章节

核验视频身份后，优先读取原站提供的字幕和章节。区分人工字幕、平台自动字幕和本地 ASR，保存语言、取得时间、来源文件及提取工具版本。不要用自动字幕冒充作者原稿。

只下载完成研究所需的媒体；实际取得的文件应可打开，记录时长和 SHA-256。请求成功、存在一个空文件或拿到视频 URL 均不代表下载完成。字幕不存在、不可访问、只取得一部分，应分别标注。

## 4. 无字幕时的音轨、ASR 与画面校正

以下方法来自原技能在 Windows 已登录 Chrome 上的历史经验，**不代表当前机器已经具备或验证过这些条件**。需要实际可播放的视频、可用的浏览器控制、音轨捕获支持及本地转写工具；缺少条件时留在待采集状态。

1. 使用用户授权的真实浏览器会话打开视频，确认播放器加载的是目标视频。需要登录时由用户完成，不导出或提交 Cookie。
2. 在播放器页面对 `<video>` 调用 `captureStream()`，仅取音轨，用 `MediaRecorder` 录为 `audio/webm;codecs=opus`。检查 API、音轨和 MIME 支持；按 2 秒分块，播放结束后停止。没有完整播放或录制中断时，记录实际覆盖区间，不能声称全片完成。
3. 如需通过临时本地 HTTP 服务接收录音，仅绑定 `127.0.0.1`，限制请求大小与允许来源，处理 `OPTIONS` 和必要 CORS 头；验证浏览器确实允许请求。原技能中的本地传输成功不保证当前浏览器策略相同。结束后关闭服务。
4. 用 PyAV 或 FFmpeg 解码为 16 kHz、单声道 WAV，再用 faster-whisper 等可用 ASR 引擎转写。原技能参考 `small`、`int8`、CPU；实际记录引擎／模型版本、参数、语言、运行设备和处理范围，不承诺原机器的耗时。
5. 保存原始 ASR 分段与修订记录。笔记按约 30 秒合并为时间戳段落，不丢弃段内信息；保留 `[mm:ss]`，超过一小时使用 `[hh:mm:ss]`，并保留原始秒数供跳转。时间是视频进度，不能与画面中的游戏计时混用。
6. 若有烧录字幕，按约 8 秒一帧抽取字幕区域作校正线索，再在不清楚处加密抽帧、回听。截图不能覆盖每一句，不能据此声称逐句核验完毕；人工可读画面与 OCR 都需检查，不能把 OCR 结果视为绝对正确。
7. 抽帧使用视频实际原生尺寸；浏览器内采样需要逐次 seek 并等待 `seeked`。原技能中的 854×480、底部 120 像素只适用于当时的视频，应按实际字幕区域调整。画布不可读时记录限制，不绕过浏览器保护。
8. 游戏录像另外保留能核对强化名称、选择顺序、装备栏、结算和版本信息的关键帧位置。原始帧保存在本地；项目文档优先引用原视频时间点，确需随仓库发布的画面另行核对许可与隐私。

本技能中的浏览器捕获、ASR 及画面校正在 2026-11-14 这批 Cloud 采集中**没有执行**；不能将此操作说明作为本批已成功转写的证据。

## 5. 每条笔记的结构

使用[视频笔记模板](video-note-template.md)，标题为 `作者：主题 - 视频笔记`。每个视频独立页面，同系列用批次索引组织；主题间交叉引用链接，不把多个视频内容覆盖进同一篇已有指南。

1. **顶部来源块**：原视频、频道／系列、发布日期、时长及内容状态。
2. **核心信息表**：视频 ID、时长、发布日期、播放量／点赞及读取时间、频道、字幕状态、章节、涉及工具、项目版本与录像版本。
3. **一句话总结**：基于实际读到的内容，不能只改写标题。
4. **📌 章节精炼**：按真实章节／视频进度整理，每项结论有时间点；没有作者章节时注明为整理者划分。
5. **可执行 Checklist**：只列有内容依据、满足条件才成立的操作；采集待办与游戏操作分开写。
6. **避坑表**：列出别做什么、为什么、证据时间点与未验证条件。
7. **时间戳记录**：有相应转载许可或用户提供文本时归档完整逐字稿；其他情况下保留原创时间戳摘要、必要短摘录及原视频链接，不复制受版权保护的全文。
8. **画面解析**：关键界面、英雄／强化／装备全名、视频时间、可见版本信息，以及证据缺口。
9. **引擎对照与存疑项**：字幕／ASR 引擎、模型参数、已修正误听、修正依据、仍存疑项与适用范围。未使用 ASR 时如实写明。

原链接、时间戳、字幕来源和校正说明都要保留。URL 紧邻全角括号时使用显式 Markdown 链接，避免 Notion 自动链接吞入括号内外文字。

## 6. 分开记录内容进度与版本复核

批次清单沿用 `schemaVersion: 1` 的字段时，保持下列语义；增添字段应说明用途。下面是继续采集时的状态约定，当前批次仅使用待采集状态。

| 单条状态 | 条件 | 文件位置 |
| --- | --- | --- |
| `pending_media_and_primary_metadata` | 缺少原站元信息或尚未取得实际内容 | `pending/` |
| `extracted` | 已取得可读取内容，记录覆盖范围与来源，尚未完成笔记 | `pending/` |
| `summarized` | 完成内容笔记及人工核对，明确剩余缺口 | `notes/` |
| `reviewed_for_patch` | 已完成笔记，且对实际引用的机制逐项完成指定补丁复核 | `notes/` |
| `excluded` | 不在窗口、频道不匹配或其他明确排除原因 | 保留清单与原因，必要时保留 `pending/` 记录 |

- `completedNotes` 只计 `summarized` 与 `reviewed_for_patch`，不计空模板；笔记完成不等于已通过补丁复核。
- `completeChannelEnumeration` 只在原站清单分页确实覆盖目标范围后置为 `true`。未完成枚举时，不能报告“一周全部处理完成”。
- `publishedAt`、`durationSeconds`、`officialCaptionsAvailable`、`chapters`、`license`、`recordedPatch` 等未知字段保持 `null`；空列表应表示已确认没有章节等内容，而不是读取失败。
- `withinWindow` 只依据足够精确的原站发布时间判定，`verifiedWithinWindow` 统计确认在窗口内的条目；日期精度不足、频道不明或源站不可读时保留未知。
- `downloadedVideos`、`downloadedAudio`、`downloadedCaptions`、`extractedFrames` 统计已验证可读取的实际产物。浏览器录制音轨与下载音轨另记取得方式，截图或链接不能计为下载了视频。
- `recordedPatch` 保存录像补丁及其证据；`videoPatchVerified` 只说明批次是否已核验所收录录像的补丁，不能代替逐项机制复核。换目录、更新抓取日期不会提高证据等级。

对游戏录像，逐条核对英雄、强化全名与拿取顺序、出装顺序、触发条件、例外和失败情形。再对照当版官方说明或可靠的一手资料复核机制。单局高光、标题极端数值和主观评价不能作为统计胜率、一般强度或必选结论。缺少补丁证据时可以作为历史／待核资料保存，不能自动导入 `data/`、组合库或产品推荐。

## 7. 验收与提交

- [ ] 清单中视频 ID 去重，频道与时间窗证据明确，覆盖缺口写入批次 README。
- [ ] `manifest.json` 可解析；状态、完成数量、文件路径与实际内容一致，移动页面后相对链接仍可用。
- [ ] 每条总结、玩法和时间戳可回查，未知项未被猜测或模板文字填充。
- [ ] 字幕／转写范围、关键帧与修正记录可核对，笔记完成与版本复核分开报告。
- [ ] Git 仅包含必要文档和已确认可分发的资料，原始媒体、会话、凭据及本地日志未被提交。
- [ ] 执行 `git diff --check`，检查新增／改动 Markdown 的本地链接与清单一致性。视频外链打不开时记录真实结果，不把格式检查当作网络验证。
- [ ] PR 按仓库模板说明实际改动、验证结果和未验证范围。产品代码或内置资料变更继续执行开发指南要求的测试、检查与 Windows 打包验收；文档结构检查不代替这些验证，未运行须明确列出。

交付时分别报告候选数量、完整枚举状态、实际取得内容数量、完成笔记数量、通过补丁复核数量。受阻时给出错误、已有产物和恢复条件，不能把建立文件夹或生成模板表述为“已完成视频笔记”。
